# pg16-cert-prep

Веб-тренажёр для подготовки к сертификации по PostgreSQL 16 на основе курса DBA1.

568 вопросов: 496 по 16 темам курса DBA1, 35 в разделе «17. Собеседование DBA» и 37 в разделе «18. Память процесса». У каждого варианта ответа есть пояснение. Тренировка по темам, экзамен с таймером и разбором ошибок, работа над ошибками, личная статистика.

## Возможности

- **Тренировка по темам.** Категории в порядке курса (01–16, затем разделы «17. Собеседование DBA» и «18. Память процесса» — они вне экзамена, но их можно включить в его настройках), на карточке видно, сколько вопросов темы уже решено («решено 12 из 30»). За один заход даётся порция из 16 вопросов, вопросы и варианты ответов перемешиваются. После ответа сразу видны верный ответ, пояснение к вопросу и пояснение под каждым вариантом.
- **Режим «Подходит или нет».** Переключатель над списком тем. Вместо четырёх вариантов показывается вопрос и один вариант ответа, нужно решить, подходит ли он. В порции 16 карточек, верных и неверных вариантов в ней поровну; после ответа видны пояснение к варианту и общее пояснение, в конце — итог «верно N из 16». Ответы этого режима хранятся отдельно и не влияют на «решено N из M», работу над ошибками и статистику; экзамен остаётся классическим. Если сервер не подтвердил ответ, выбор остаётся прежним и повтор отправляет тот же ответ.
- **Три формата вопросов.**
  - один правильный ответ из четырёх или пяти;
  - несколько правильных ответов (подсказка «выберите один или более»), засчитывается только полное совпадение;
  - «дополните код»: фрагмент с пропуском `___` и четыре варианта вставки.
- **Экзамен.** 20, 30 или 50 случайных вопросов из выбранных тем, таймер (1,5 минуты на вопрос), возврат к предыдущим вопросам, порог сдачи 70%. В конце процент, результат по темам и разбор ошибок с пояснениями.
- **Материал для изучения.** К разделу «17. Собеседование DBA» есть текст для подготовки: суть, образцовые ответы, типичные уточняющие вопросы и практика в консоли на учебном кластере. Лежит в `docs/INTERVIEW.md`, на сайте открывается ссылкой «Материал для изучения» под разделом 17 (только после входа).
- **Незавершённый экзамен не теряется.** Ход экзамена хранится в браузере (отдельно для каждого пользователя): после закрытия вкладки на экране категорий появляется плашка «Продолжить экзамен» или «Завершить экзамен». Таймер идёт и пока вкладка закрыта; если время вышло, экзамен при следующем открытии завершается сам с теми ответами, что успели дать. Правильные ответы в браузере не хранятся. При выходе сохранённый экзамен удаляется.
- **Работа над ошибками.** Журнал ответов: вопрос попадает в список, если последний ответ на него был неверным, и уходит из него после верного.
- **История экзаменов.** Дата, результат, «Сдан» или «Не сдан» и затраченное время для последних 50 экзаменов.
- **Вход по ссылке или коду из письма.** Пользователь вводит email и получает письмо с одноразовой ссылкой и 6-значным кодом (действуют 15 минут, войти можно одним из способов). Код удобен, если почта открыта на другом устройстве. После 5 неверных попыток код блокируется; ссылка остаётся действительной до использования или истечения срока. Пароли не хранятся, сеанс длится 30 дней.
- **Личная статистика.** Ответы, ошибки и экзамены у каждого пользователя свои. «Моя статистика» показывает по темам, сколько вопросов решено, долю верных ответов и сколько вопросов сейчас в ошибках.
- **Роль админа.** Админ видит список пользователей с их результатами, статистику любого пользователя и трудные вопросы — 20 вопросов с самой высокой долей ошибок.
- Светлая и тёмная тема по настройке системы.

Правильные ответы не отдаются браузеру вместе с вопросами: проверка выполняется на сервере.

## Стек

Node.js, Express 5, `pg`, PostgreSQL. Запросы пишутся на нативном SQL без ORM. Страница на чистых HTML, CSS и JS без сборки и зависимостей.

## Требования

- Node.js 20 или новее (проверено на 20 и 22): этого требует nodemailer.
- PostgreSQL 14 или новее (проверено на 14.7).
- Клиент `psql`.

## Установка

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте базу данных и роль PostgreSQL для приложения (имена выберите сами).

3. Скопируйте шаблон настроек и заполните его. Файл `.env` в репозиторий не попадает.

   ```bash
   cp .env.example .env
   ```

   | Переменная | Назначение |
   |---|---|
   | `PORT` | порт приложения (по умолчанию 3000) |
   | `HOST` | адрес, на котором слушает приложение (необязательно, по умолчанию `127.0.0.1`, то есть только этот компьютер) |
   | `NODE_ENV` | необязательно: при значении `production` отключается `GET /api/test` |
   | `DB_HOST`, `DB_PORT` | адрес и порт PostgreSQL |
   | `DB_NAME`, `DB_USER`, `DB_PASS` | база, роль и пароль |
   | `APP_URL` | адрес сайта для ссылок в письмах, например `https://pg.example.ru`; обязателен при `NODE_ENV=production`, иначе по умолчанию `http://HOST:PORT` |
   | `SMTP_HOST`, `SMTP_PORT` | почтовый сервер для писем со ссылкой (порт 587 — STARTTLS, 465 — TLS) |
   | `SMTP_USER`, `SMTP_PASS` | ящик и пароль для отправки |
   | `SMTP_FROM` | адрес отправителя |
   | `AUTH_SECRET` | секрет для HMAC кода из письма, не меньше 32 случайных байт (например `openssl rand -hex 32`); обязателен при `NODE_ENV=production`, при разработке без него берётся случайный на время работы процесса |

4. Примените миграции по порядку. Каждую нужно выполнить один раз: миграции 002, 003 и 006 добавляют вопросы и при повторном запуске задублируют их, 017 при повторном запуске завершится ошибкой.

   Миграции 017 нужен email владельца сайта: он становится первым админом, и ему передаются уже накопленные ответы и экзамены. Замените `owner@example.ru` на свой адрес.

   ```bash
   set -a; . ./.env; set +a
   for f in migrations/*.sql; do
     PGPASSWORD="$DB_PASS" psql -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" -v ON_ERROR_STOP=1 -v owner_email=owner@example.ru -f "$f"
   done
   ```

   Что делает каждая миграция, написано в комментарии в начале её файла. Миграция 001 создаёт таблицу `tasks` для учёта хода работы; к тренажёру она не относится, её можно пропустить.

5. Запустите сервер и откройте <http://localhost:3000>:

   ```bash
   npm start
   ```

   Для разработки с автоперезапуском: `npm run dev`.

## API

Все пути, кроме `/api/auth/*` и `/api/client-errors`, требуют входа (cookie сеанса). Ответы, ошибки и экзамены относятся к вошедшему пользователю.

Ограничения частоты (в памяти процесса, ответ 429): запрос письма — 20 в час с IP и не больше 1 в минуту и 5 в час на адрес; проверка кода — 30 в час с IP; просмотр владельца ссылки — 30 в час с IP; ответы и создание порций суммарно — 1000 в час на пользователя; проверка экзамена — 20 в час на пользователя; отчёты страницы о сбоях — 30 в час с IP. Приложение отдаёт заголовки безопасности: CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, в продакшене — HSTS.

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/request` | отправить ссылку для входа: `{email}` |
| `POST /api/auth/peek` | по токену из ссылки вернуть email её владельца, не расходуя ссылку: `{token}` (для экрана «Вход как …») |
| `POST /api/auth/verify` | войти по токену из ссылки: `{token}`, ставит cookie сеанса |
| `POST /api/auth/verify-code` | войти по коду из письма: `{email, request_id, code}`, `request_id` возвращает `POST /api/auth/request`; ставит cookie сеанса |
| `POST /api/auth/logout` | выйти |
| `GET /api/me` | email и роль вошедшего пользователя |
| `GET /api/stats` | личная практика по темам |
| `GET /api/admin/users` | только админ: пользователи и их результаты |
| `GET /api/admin/users/:id` | только админ: практика по темам и экзамены пользователя |
| `GET /api/admin/hard-questions` | только админ: 20 вопросов с самой высокой долей ошибок (не меньше 3 ответов) |
| `GET /api/materials/interview` | текст `docs/INTERVIEW.md` (Markdown) для вошедших пользователей |
| `GET /api/categories` | категории с числом вопросов и признаком `in_exam` |
| `GET /api/questions?category_id=` | вопросы категории без ответов |
| `POST /api/training/batches` | сохранить и выдать порцию: `{category_id, limit: 16}` или `{mode: "mistakes"}`; возвращает `id`, `created_at`, `questions` в сохранённом порядке |
| `GET /api/training/batches?before=` | личная история порций, по 50 записей; `next_before` — курсор следующей страницы |
| `GET /api/training/batches/:id` | снимок своей порции со всеми вопросами, порядком вариантов и выбранными ответами |
| `POST /api/answers` | проверка ответа: `{question_id, answer, training_batch_id}`; номер порции обязателен для нового интерфейса, старые клиенты могут его не передавать; несколько букв пишутся слитно, например `"AC"` |
| `POST /api/option-checks/batches` | порция карточек режима «Подходит или нет»: `{category_id}`; возвращает `id` и до 16 карточек `{question_id, question_text, option_text, multi}`, верный ли вариант, не раскрывается |
| `POST /api/option-checks` | ответ на карточку: `{batch_id, question_id, fits}`, где `fits` — булево значение; возвращает `right`, `option_fits`, пояснение варианта и общее пояснение; повтор того же ответа возвращает сохранённый результат, смена ответа — 409 |
| `GET /api/exam?count=&categories=` | случайные вопросы для экзамена без ответов; без `categories` — только из тем с `in_exam` |
| `POST /api/exam/check` | проверка всех ответов экзамена, итог и порог сдачи |
| `GET /api/mistakes` | вопросы, на которые последний ответ был неверным |
| `GET /api/exam/history` | последние 50 завершённых экзаменов |
| `GET /api/test` | проверка соединения с базой (кроме `NODE_ENV=production`) |
| `POST /api/client-errors` | отчёт страницы о сбое для журнала сервера, вход не нужен: `{kind, path, status, ms, screen, source, line}`. Принимаются только эти поля, путь, экран и файл — из списков допустимых значений, тело до 2 КБ; ответ 204 без подробностей (429 при превышении лимита, 413 для слишком большого тела) |

## Журнал и ограничения по времени

Ни один запрос не ждёт бесконечно: каждый следующий уровень ждёт дольше предыдущего, поэтому ошибку первым замечает сервер, а не nginx.

| Уровень | Ограничение |
|---|---|
| получение соединения из пула | 3 с |
| запрос к PostgreSQL | 5 с (`statement_timeout`), на стороне Node — 6 с (`query_timeout`) |
| запрос письма для входа целиком, вместе с отправкой письма | 12 с |
| ожидание ответа на странице | 15 с |
| nginx (`proxy_read_timeout`) | 60 с |

Если сервер не ответил, страница сообщает «Сервер не ответил, ответ не сохранён — нажмите «Ответить» ещё раз». Выбор при этом остаётся заблокированным, а повтор отправляет тот же ответ: сервер мог его уже сохранить.

Сервер пишет в журнал службы одну строку на каждый запрос API, который завершился ошибкой, выполнялся дольше 2 с или был оборван, а также отчёты страницы о сбоях:

```
api POST /api/answers 500 5012ms user=12 err=DatabaseError/57014
client timeout path=/api/answers status=0 ms=15003 screen=question user=12 source=-:0
```

В строке — шаблон маршрута, код ответа, длительность, номер пользователя, класс и код ошибки. Текст ошибки, тела запросов, cookie и адреса почты в журнал не попадают.

Посмотреть журнал, если приложение работает службой systemd `pg16-cert-prep`:

```bash
journalctl -u pg16-cert-prep --since today --no-pager -o cat | grep -E "^(api|client|error) "
```

## Копия базы с сервера на Mac

Автоматическая копия базы создаётся на сервере каждый день в 03:30 (cron, хранятся 14 последних). Чтобы копия пережила потерю сервера, её скачивает на Mac скрипт `scripts/pull-server-backup.sh`:

- берёт самую свежую копию `pg16_cert-*.sql.gz` с сервера (по `ssh appuse`, на сервере только читает);
- проверяет её: контрольная сумма SHA-256 совпала с серверной, `gzip -t`, внутри есть данные таблицы вопросов;
- кладёт в `~/Backups/pg16-server/` (права 700, файлы 600), хранит 12 последних, старые удаляет только там;
- пишет журнал `pull.log`; при ошибке показывает уведомление macOS.

Копии содержат электронные адреса пользователей, поэтому хранятся только в этой папке с закрытыми правами.

```bash
scripts/install-pull-backup.sh            # поставить задачу launchd: ежедневно в 12:00 и при входе в систему
scripts/install-pull-backup.sh --remove   # убрать задачу (скачанные копии остаются)
bash scripts/pull-server-backup.sh        # скачать вручную
```

Скачивается только новая копия: ежедневная проверка в 12:00 забирает свежую серверную копию, а если Mac был выключен, копия подтянется при следующем включении. Для работы нужен вход на сервер по ключу без пароля (`ssh appuse`).

### Проверка восстановления

14.10.2026 проверена копия `pg16_cert-20261014-033001.sql.gz`: SHA-256 файла на Mac совпал с серверным. Серверный файл восстановлен без изменения SQL в отдельный временный кластер PostgreSQL 16.14 на сервере, доступный только через закрытый Unix-сокет. Восстановление выполнено с `ON_ERROR_STOP=1` в одной транзакции; рабочая база не затрагивалась.

Число строк совпало с дампом во всех семи таблицах: 17 категорий, 496 вопросов, 79 ответов, 2 пользователя, 4 запроса входа, 2 сеанса и пустая история экзаменов. Проверены связи, ограничения, индексы, последовательности ID и наличие пояснений ко всем вариантам. На восстановленной базе прошли все 44 API-теста; временный кластер затем удалён. Эта проверка подтверждает восстановление данных указанной копии, но не восстановление всего сервера: настройки служб и секреты приложения в дамп БД не входят.

Для восстановления нужен клиент `psql`, поддерживающий команды `\restrict` / `\unrestrict` из современных дампов. Установленный на Mac `psql` 17.4 такой дамп не восстанавливает; проверка выполнена клиентом 16.14 на сервере. Защитные команды из дампа удалять не нужно. В ветке 17 поддержка появилась в [PostgreSQL 17.6](https://www.postgresql.org/docs/release/17.6/).

## Тесты

```bash
npm test
```

Запускаются все тесты без браузера: API, журнал и ограничения по времени, миграции вопросов и пояснений. Тесты работают с базой из `.env`. Они создают временных пользователей с адресами `test-…@example.test` и `logging-…@example.test` и удаляют их по окончании вместе со всеми их ответами и экзаменами. Временные вопросы создаются и удаляются в ходе самих тестов. Письма в тестах не отправляются.

Браузерные регрессионные проверки используют ту же локальную базу с применёнными миграциями и Playwright из devDependencies:

```bash
npx playwright install chromium
npm run test:browser
```

Вместо установки Chromium можно указать путь к установленному браузеру через `BROWSER_EXECUTABLE_PATH`. Тесты запускают приложение на случайном локальном порту, создают пользователей `browser-…@example.test` и удаляют их вместе с ответами и экзаменами. Проверяются задержанные и повторные ответы, ошибки завершения экзамена, восстановление попытки и узкие экраны. Ход времени в браузере управляется тестом; ждать 30 минут не требуется.

Результаты исправления замечаний темы 01: [отчёт от 14.10.2026](docs/LEARNING-FIXES-2026-10-14.md).

Замена 16 смысловых повторов: [формулировки, источники и проверки](docs/QUESTION-REPLACEMENTS-2026-10-15.md). Миграция 029 собирается командой `node scripts/gen-question-replacements.js`. Проверка её повторного запуска и отката ошибок: `node --test tests/question-replacements.test.js` (на временных копиях таблиц локальной БД).

В «Истории тренировок» доступны все выданные порции с исходным текстом вопросов, порядком вариантов и ответами. Работа над ошибками сохраняется отдельной порцией. История начинается после установки миграции 028 и выпуска нового кода; старые порции задним числом не восстанавливаются. Подробности: [история тренировок](docs/TRAINING-HISTORY-2026-10-14.md), [проверка повторов во всех разделах](docs/QUESTION-DUPLICATES-2026-10-14.md).

## Учебные примеры: стек и куча

В `examples/` лежат два примера к теме устройства памяти процесса. К тренажёру они не относятся, сайт их не отдаёт.

- `stack-heap.c` — на C, как и сам PostgreSQL. Показывает адреса окружения, стека, кучи, данных и кода; кадры стека; память от `malloc`, которая появляется в оперативной памяти только при записи; переполнение стека в отдельном процессе, созданном через `fork`.
- `stack-heap.js` — то же на Node.js: глубина рекурсии, время жизни объектов, рост и освобождение кучи, утечка памяти.

Пример на C (нужен компилятор: в macOS — Xcode Command Line Tools, в Debian и Ubuntu — пакет `build-essential`). Ключ `-O0` отключает оптимизацию, иначе компилятор может убрать рекурсию и переменные:

```bash
cc -O0 -Wall -o /tmp/stack-heap examples/stack-heap.c && /tmp/stack-heap
```

Пример на Node.js (`--expose-gc` разрешает вызывать сборщик мусора вручную):

```bash
node --expose-gc examples/stack-heap.js
```
