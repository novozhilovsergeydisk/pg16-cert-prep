# Отдельный Node.js для pg16-cert-prep

Служба приложения использует официальный Node.js 24.22.2 LTS из
`/opt/pg16-cert-prep/node-v24.22.2-linux-x64`. Системный `/usr/bin/node`, npm и другие службы
этот способ установки не меняет. Linux x86_64 runtime загружается с nodejs.org;
исходники приложения и шаблон systemd доставляются только через git.

## Подготовка

Перед изменением сохранить действующий unit и весь каталог его drop-in с закрытыми правами,
зафиксировать версии, процессы и состояние соседних сайтов. Убедиться, что git-копия чистая.
Для установки нужны root, curl, gpgv, tar с xz и стандартные утилиты Debian. Пакеты ОС
скрипт не устанавливает. Для runtime и временного архива требуется запас свободного места.

После получения согласованного коммита через git выполнить в каталоге приложения:

```bash
bash scripts/install-node-lts.sh
```

Скрипт проверяет подпись SHASUMS256.txt.asc по закреплённому отпечатку подписанта и keyring
из указанного коммита nodejs/release-keys, затем сравнивает SHA-256 архива с закреплённой суммой.
Существующий целевой каталог он не перезаписывает. Временные файлы удаляются после завершения.
Скрипт устанавливает runtime, но не меняет и не перезапускает службу.

Ссылки на выпуск и проверку: [Node.js 24.22.2](https://nodejs.org/en/blog/release/v24.22.2),
[проверка бинарных файлов](https://github.com/nodejs/node#verifying-binaries).

## Переключение службы

Сначала проверить загрузку зависимостей и соединение с БД под новым Node из-под pgcert,
а также HTTP/TLS-проверки на Linux. Перед переключением убедиться, что текущий ExecStart
соответствует сохранённой конфигурации и файл 20-node-lts.conf ещё не существует.

```bash
install -m 644 -o root -g root deploy/systemd/20-node-lts.conf \
  /etc/systemd/system/pg16-cert-prep.service.d/20-node-lts.conf
systemd-analyze verify /etc/systemd/system/pg16-cert-prep.service
systemctl daemon-reload
systemctl restart pg16-cert-prep
```

Drop-in задаёт полный путь ExecStart и PATH только для pg16-cert-prep; ai.conf, EnvironmentFile
и остальные настройки сохраняются. Проверить active, фактический `/proc/<MainPID>/exe`,
версию работающего процесса, HTTPS, доступность БД и прежнее состояние соседних служб.
`/usr/bin/node --version` должен показывать исходную версию.

## Откат

Если до перехода 20-node-lts.conf отсутствовал, переместить только созданный файл из каталога
службы в закрытый каталог резервной копии, затем выполнить daemon-reload и restart только
pg16-cert-prep. Исходный unit снова запустит `/usr/bin/node server.js`. Если файл существовал
до начала работ, использовать сохранённую копию вместо удаления или автоматической замены.
После отката проверить процесс, HTTPS и соседние службы. Runtime в /opt можно оставить:
его наличие само по себе не меняет способ запуска.

Для последующих обновлений изменить версию, SHA-256 и при необходимости отпечаток/keyring
в установщике и путь в drop-in одним согласованным изменением; повторить проверки до переключения.
