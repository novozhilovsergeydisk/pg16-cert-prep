# ТЗ: тренажёр подготовки к сертификации PostgreSQL 16

Первоначальное ТЗ утверждено 09.10.2026. Актуализировано 14.10.2026 по текущей реализации и завершённым задачам: авторизация, статистика и вопросы с несколькими ответами теперь входят в версию. Новые возможности согласуются отдельно.

## Цель

Веб-тренажёр на русском языке для подготовки к сертификации PostgreSQL 16 по курсу DBA1 и к собеседованию DBA.

## Категории и вопросы

- 16 тем курса в порядке «01. …» — «16. …» и отдельный раздел «17. Собеседование DBA».
- 496 вопросов: 461 по курсу и 35 для собеседования. Загрузка и исправления — через SQL-миграции.
- Три формата: один правильный ответ, несколько правильных ответов, дополнение кода. Для нескольких ответов требуется полное совпадение выбранного набора.
- У каждого вопроса есть общее пояснение и пояснение к каждому варианту. Текст поддерживает фрагменты и блоки кода.
- Карточка темы показывает число вопросов и личный прогресс «решено N из M»: сколько разных вопросов пользователь уже ответил хотя бы раз.
- Материал для подготовки к собеседованию находится в `docs/INTERVIEW.md` и доступен с сайта после входа.

## Тренировка и работа над ошибками

- Пользователь выбирает тему и получает порцию до 16 вопросов, по одному на экране.
- При выборе порции сначала идут вопросы без ответа, затем вопросы с неверным последним ответом, затем отвеченные верно — давно отвеченные раньше. Вопросы выбранной порции и варианты ответа перемешиваются.
- После ответа сервер возвращает результат проверки, правильный ответ и пояснения. До проверки правильные ответы и пояснения вместе с вопросами не передаются.
- На экране есть счётчик текущего вопроса в порции; после завершения можно открыть тему снова.
- В «Работу над ошибками» попадают вопросы, на которые последний ответ пользователя неверный. Верный ответ убирает вопрос из этого списка.
- Для последующего анализа сохраняются пользователь, раздел или режим работы над ошибками, время выдачи, снимок всех вопросов и вариантов, порядок показа. В интерфейсе доступна личная «История тренировок» с постраничной загрузкой и просмотром порции, включая вопросы без ответа. Реализация подготовлена локально 14.10.2026.
- Ответ сохраняется с номером порции, выбранными вариантами, временем и результатом. Повтор того же ответа в одной порции не создаёт ещё одну запись; изменение уже сохранённого ответа отклоняется. Проверка использует снимок вопроса на момент выдачи.
- Старые ответы остаются без номера порции. История экзаменов сохраняет прежний формат; новая история относится к тренировкам и работе над ошибками.

## Экзамен

- Выбор 20, 30 или 50 вопросов, по умолчанию 30, и выбор тем. По умолчанию отмечены темы курса; раздел собеседования можно включить вручную (`in_exam = false`).
- Случайные вопросы, таймер по 1,5 минуты на фактически выданный вопрос, переходы к предыдущим вопросам и изменение ответа до завершения.
- При истечении времени экзамен завершается автоматически; неотвеченные вопросы считаются ошибками. Проверка выполняется на сервере, порог сдачи — 70%.
- Итог: процент, «Сдан» / «Не сдан», результат по темам и разбор ошибок с пояснениями.
- Результаты сохраняются для пользователя. История показывает последние 50 экзаменов, включая дату и затраченное время.
- Незавершённый экзамен сохраняется в `localStorage` отдельно для пользователя: вопросы, выбранные ответы, позиция и время. Правильные ответы туда не записываются.
- После закрытия вкладки время продолжает идти. При возвращении можно продолжить или завершить экзамен; если срок истёк, он завершается с сохранёнными ответами. Сохранение зависит от доступности хранилища браузера; при выходе сохранённый экзамен удаляется.

## Вход и роли

- Вход по email без пароля: письмо содержит одноразовую ссылку и шестизначный код со сроком действия 15 минут. Успешный вход одним способом погашает оба.
- Проверка кода требует номер запроса, полученный страницей при отправке письма. После пяти неверных попыток код блокируется; ссылка остаётся действительной до использования или истечения срока.
- Перед входом по ссылке страница показывает адрес аккаунта и запрашивает подтверждение.
- Сеанс действует 30 дней. Cookie — `HttpOnly`, `SameSite=Lax`, в продакшене также `Secure`.
- При выходе сервер удаляет сеанс, клиент очищает сохранённый экзамен и данные незавершённого входа, затем перезагружает страницу.
- Роли: `user` и `admin`. Ответы, ошибки, экзамены и статистика относятся к текущему пользователю.
- Личная статистика показывает по темам число отвеченных вопросов, долю верных ответов среди всех попыток и число текущих ошибок.
- Админ видит пользователей и их результаты, статистику и экзамены выбранного пользователя, а также 20 вопросов с самой высокой долей ошибок: учитываются вопросы минимум с тремя ответами и хотя бы одной ошибкой.

## API и защита

- API тренажёра, статистики и материалов требует входа. Административные маршруты дополнительно проверяют роль.
- Вопросы выдаются без правильных ответов; тренировка и экзамен проверяются сервером. SQL-запросы параметризованные.
- Запросы `POST` с чужим `Origin` отклоняются. Настроены CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`; HSTS включён в продакшене.
- Ограничения частоты: запрос письма — 20 в час с IP, 1 в минуту и 5 в час на адрес; проверка кода и просмотр владельца ссылки — по 30 в час с IP; ответы и создание порций суммарно — 1000 в час на пользователя; проверка экзамена — 20 в час на пользователя. Превышение возвращает HTTP 429.
- Ограничения по IP и пользователю хранятся в памяти одного процесса; ограничения отправки на email проверяются в БД.
- `GET /api/test` доступен только вне продакшена. Полный перечень маршрутов и параметров приведён в [README](../README.md#api).

## Существующая схема БД

| Таблица | Назначение и основные поля |
|---|---|
| `categories` | `id`, уникальное `name`, `in_exam` |
| `questions` | `id`, `category_id`, `question_text`, `options` (`jsonb`), `correct_answer` (`varchar(8)`), `explanation`, `option_notes` (`jsonb`) |
| `users` | `id`, уникальный email в нижнем регистре, `role`, даты создания и последнего входа |
| `login_tokens` | хеш ссылки, email, сроки действия, время использования, HMAC кода, число попыток, хеш номера запроса |
| `sessions` | хеш идентификатора сеанса, `user_id`, время создания и истечения |
| `answer_log` | `id`, `user_id`, `question_id`, результат проверки и время ответа |
| `training_batches` | `id`, `user_id`, `category_id`, название раздела, режим, время выдачи и снимок вопросов с порядком показа |
| `exam_history` | `id`, `user_id`, время завершения, число вопросов и верных ответов, процент, результат сдачи и длительность |

Миграция 028 добавляет в `answer_log` поля `training_batch_id` и `selected_answer`; для одной порции и вопроса допускается одна запись ответа.

Таблица `tasks` используется отдельно для учёта разработки, для работы тренажёра не обязательна. Структуру и ограничения задают миграции; порядок установки описан в README. Пароли пользователей не хранятся, идентификаторы сеансов и одноразовых ссылок хранятся только в виде хешей.

## Технические ограничения и эксплуатация

- Node.js 20+, Express 5, `pg`, PostgreSQL; нативный SQL без ORM, PostgreSQL без Docker.
- Интерфейс на HTML, CSS и JavaScript без сборки; светлая и тёмная тема по настройке системы.
- Секреты находятся в `.env`, не попадают в вывод и репозиторий. Права файлов ограничивают доступ нужными системными пользователями.
- Размещение: `pg.appuse.ru`, nginx, systemd и PostgreSQL 16.
- Серверная копия БД создаётся ежедневно в 03:30, хранятся 14 последних. Скрипт скачивания на Mac сохраняет до 12 копий, проверяет SHA-256, целостность gzip и наличие данных вопросов. Расписание launchd — ежедневно в 12:00 и при входе в систему.
- Результат пробного восстановления и ограничения совместимости клиента описаны в [README](../README.md#проверка-восстановления).
- На общем сервере 14.10.2026 архивированы неиспользуемые проекты, закрыт доступ к их исходным каталогам, отключён неиспользуемый PHP-FPM и запрещён вход `testuser`. Проверки и откат описаны в [отчёте по задаче №29](SERVER-ISOLATION-PLAN.md).
- Проверки API находятся в `tests/api.test.js`; тестовые письма не отправляются. Коммит и деплой требуют отдельного прямого разрешения пользователя на текущие изменения.
