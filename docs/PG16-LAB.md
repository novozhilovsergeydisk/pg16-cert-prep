# Учебный PostgreSQL 16 на Linux

Задача 224. Подготовка выполнена 9–10 ноября 2026 года по поручению пользователя:
сначала команды выполнял пользователь, завершение и проверку — агент.

## Подключение

С Mac:

```bash
ssh foolish-magenta
```

В открывшейся оболочке root, вход в psql:

```bash
sudo -u postgres /usr/lib/postgresql/16/bin/psql -X -p 5432 -d postgres
```

Выход из psql: `\q`. Для упражнений с несколькими сеансами открыть несколько
SSH-подключений и выполнить ту же команду в каждом.

## Параметры стенда

- Ubuntu 26.04 amd64; PostgreSQL 16.15 из официального PGDG.
- Кластер `16/main`, владелец ОС и суперпользователь БД — `postgres`.
- Порт 5432; TCP только `127.0.0.1`, Unix-сокет `/var/run/postgresql`.
- Локальная аутентификация `peer`, TCP — `scram-sha-256`; пароль для postgres не задавался.
- Данные: `/var/lib/postgresql/16/main`.
- Конфигурация: `/etc/postgresql/16/main/postgresql.conf`.
- Журнал: `/var/log/postgresql/postgresql-16-main.log`.
- Локаль `C.UTF-8`, кодировка UTF8; сообщения и сортировка могут отличаться от примеров.
- Контрольные суммы страниц выключены — исходное значение initdb PostgreSQL 16.
- Служба `postgresql@16-main.service`, автозапуск включён.
- Для этой службы: `MemoryMax=512M`, `CPUQuota=50%`.
  Настройка: `/etc/systemd/system/postgresql@16-main.service.d/90-lab-limits.conf`.
- Автоматическое создание кластеров при установке новых серверных пакетов отключено:
  `/etc/postgresql-common/createcluster.conf`, `create_main_cluster = false`.

Статус и управление из оболочки root:

```bash
pg_lsclusters
systemctl status postgresql@16-main.service --no-pager
systemctl restart postgresql@16-main.service
```

Лимиты относятся к процессам этой службы. Прямой запуск через `pg_ctl` и отдельные
кластеры репликации ими не ограничиваются; такие упражнения требуют отдельной
настройки. На машине также работают VPN, бот и шлюз ИИ. Для обычного управления
основным учебным кластером использовать указанную службу systemd.

## Проверка готовности

Проверены подключение под postgres, локальный listener и отсутствие ошибок
в pg_hba.conf. Временные база, табличное пространство и таблица созданы;
после перезапуска сохранились 10 строк с суммой 55. Проверены отказ удаления
непустого пространства, перенос базы в pg_default, DROP TABLESPACE, DROP DATABASE
и удаление оставшегося пустого каталога через rmdir. SET/RESET random_page_cost
проверены в транзакции с откатом. Временные объекты удалены; остались только
стандартные базы и пространства, pg_default без дополнительных параметров.

В cgroups подтверждены `memory.max=536870912`, `cpu.max=50000 100000`, OOM=0.
VPN сохранил PID 1495, время запуска 2026-10-30T08:51:49.066272169Z и Restarts=0.
Docker и snt-bot сохранили PID 1015 и 1023 и прежние времена запуска.
Git-копия шлюза ИИ чистая, HEAD 63e6a1a, код читается пользователем pg16-ai;
реальный вызов провайдера при этой проверке не выполнялся.

Закрытые резервные копии находятся на сервере в `/root/pg16-lab-backups/`.
Перед окончательной правкой создан каталог `agent-fix-20261109T212037Z`:
копия конфигурации, список служб и логическая копия пустого кластера перед тестами
`before-smoke.sql`. Архивы первоначальных этапов сохранены. Полное восстановление
из этих резервных копий не проверялось.

Первоначальный запуск не удался из-за лишних кавычек в listen_addresses;
последующая попытка через pg_conftool добавила вторую некорректную строку.
Обе заменены одной строкой `listen_addresses = '127.0.0.1'`, корректность проверена
через `postgres -C listen_addresses`, затем успешным запуском и SQL-запросом.
