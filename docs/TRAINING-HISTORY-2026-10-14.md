# История тренировок — 14 октября 2026

Я добавил сохранение выданных порций и личную «Историю тренировок» для самостоятельного анализа вопросов. Изменения подготовлены и проверены локально; коммит, деплой и миграцию на сервере я не выполнял.

## Что сохраняется

- Пользователь, раздел или режим «Работа над ошибками», время выдачи и номер порции.
- Все вопросы выданной порции, включая те, на которые пользователь не ответил: ID, исходный текст, варианты, порядок вопросов и порядок вариантов.
- Выбранные варианты, время ответа и результат проверки, связанные с конкретной порцией.

Я сохраняю снимок на сервере до выдачи порции браузеру. Если запись не удалась, тренировка не начинается без истории. Повтор того же ответа в одной порции возвращает результат без второй записи в статистике. Попытка изменить уже сохранённый ответ возвращает 409. Повторная попытка в новой порции или в работе над ошибками учитывается отдельно.

Сервер проверяет ответ по снимку вопроса на момент выдачи. Последующее редактирование банка вопросов не меняет текст старой порции и её ключ ответа. Правильные ответы и пояснения снимка не возвращаются в API выдачи и просмотра истории; они выдаются при проверке ответа, как и раньше.

## Самостоятельный просмотр

На экране категорий появилась кнопка **«История тренировок»**. Список показывает раздел, дату, номер порции и число ответов. Порция открывается целиком: вопросы идут в сохранённом порядке, варианты сохраняют свои буквы, выбранные варианты отмечены, показаны результат и время ответа или «Без ответа».

История загружается страницами по 50 порций с кнопкой «Показать ещё». Можно просматривать все накопленные страницы, а не только последние 50 записей. Каждый пользователь видит только свою историю. История работы над ошибками отличается от обычных порций названием и режимом.

Это журнал **выданных наборов**, а не доказательство прочтения каждого вопроса: например, запрос мог завершиться после перехода на другой экран. Запоздалая выдача теперь не закрывает уже открытую историю. Неотвеченные вопросы видны, но время их фактического просмотра отдельно не регистрируется.

Старые порции задним числом не восстанавливаются. Прежний журнал ответов остаётся без номера порции; история экзаменов сохраняет прежний формат. Вопросы по результатам [проверки смысловых повторов](QUESTION-DUPLICATES-2026-10-14.md) в этом этапе не изменялись.

## Применение на сервере после разрешения на выпуск

Сначала нужна новая серверная резервная копия и доставка согласованных файлов. До переключения на новый код необходимо применить миграции 027 и 028. Роль приложения на сервере имеет необходимые права на схему и существующий журнал ответов; проверка прав была только чтением.

Команда для ручного выполнения на сервере использует существующий модуль подключения, не выводит реквизиты и создаёт новую таблицу от имени той же роли приложения:

```bash
cd /var/www/pg16-cert-prep
DOTENV_CONFIG_QUIET=true node <<'JS'
const fs = require('node:fs');
const pool = require('./src/config/db');
(async () => {
    try {
        for (const file of ['027_topic_01_clarifications.sql', '028_training_batches.sql']) {
            await pool.query(fs.readFileSync('migrations/' + file, 'utf8'));
            console.log(file + ': OK');
        }
    } catch (_) {
        console.error('Не удалось применить миграцию');
        process.exitCode = 1;
    } finally {
        await pool.end();
    }
})().catch(() => {
    console.error('Не удалось завершить подключение');
    process.exitCode = 1;
});
JS
```

Если миграция завершилась ошибкой, новый код выпускать нельзя. При успехе старый код совместим с расширенной схемой до переключения приложения. В этом этапе команда на сервере не выполнялась.
