# Согласованный первый этап — локальная реализация

Этот документ сохраняет состояние локальной подготовки до выпуска.
Последующее завершение: [выпуск на appuse](release.md), код `ef1c8f2`.

Я реализовал согласованные ограничения API, проверки ссылки, снимков тренировок
и новых отказов ИИ. Я подготовил конфигурации nginx и systemd и
[порядок выпуска](../../SECURITY-LIMITS.md). Учёт: задача 234.

## Что подготовлено

- Общий API bucket 10/с с ёмкостью 20 до разбора тела и обращения к БД;
  `/auth/verify` — 10 попыток/мин с IP.
- Миграция 145: атомарные общие квоты двух таблиц снимков — 1000/50 МиБ на
  пользователя и 500 МиБ на проект. Существующая история сохраняется.
- Отказы ИИ: новые сообщения не записываются, первые 100 отказов на
  пользователя/UTC-сутки содержат только метаданные; далее суточный счётчик.
  Счётчик переживает перезапуск приложения и удаляется с аккаунтом.
- Седьмой раздел SQL/JSON-отчёта показывает полное число отказов отдельно от
  ограниченного подробного журнала; документы и проверки формата актуализированы.
- Фрагменты nginx и systemd: входной API-лимит, 384 МиБ, CPUQuota=100%, TasksMax=64.

- До локальной миграции создана закрытая копия
  `/private/tmp/pg16-security234/before145.dump`, pg_restore --list успешен;
  полный restore не выполнялся. Миграция применена локально дважды.
- Полный npm test: 232/232. Включает семь новых сценариев: burst/refill/IP,
  ограничение проверки ссылки до получения соединения, точность счётчиков,
  обе байтовые границы и откат записи, гонка за последнее место между двумя
  режимами, параллельные отказы ИИ около границы 100 и переход UTC-суток.
  Байтовые границы тестируются предварительным заполнением счётчика внутри
  откатываемой транзакции, без размещения 500 МиБ фиктивных данных.
- Отдельный набор parser/SMTP/AI ранее прошёл 42/42; серверный ИИ после финальных
  изменений прошёл 28/28.
- Браузер: выбранные 54 сценария входа, тренировок, навигации и ИИ.
  Первый прогон 50/54: четыре быстрых серии reload превысили API bucket.
  После приведения fixture продолжения к штатному темпу все 12 сценариев
  этого набора прошли. Остальные 42 прошли первоначальный прогон.
  Полный test:browser с генерацией исторических скриншотов не запускался.
- После тестов счётчики квот совпали с фактическими count/sum двух таблиц,
  тестовые аккаунты limits-* отсутствуют.
- Nginx -t на временной локальной конфигурации с обоими фрагментами успешен.
  Первая команда вывела предупреждение о недоступном стандартном каталоге
  журнала; повторная с явным `-e` в закрытом временном каталоге прошла чисто.
  На macOS действующие cgroup-лимиты systemd не проверяются: это этап выпуска.
- Git diff --check и проверки синтаксиса JS успешны; новые файлы проверены
  по сильным шаблонам ключей, совпадений нет. Секреты не включены в материалы.

Первый массовый API-прогон получил 61 отказ из 98 тестов: автоматизация отправляла
запросы без задержек с одного IP. После введения темпа штатного клиента API 63/63
прошёл. Первый общий прогон затем дал 230/232: старые тесты журнала и карточек
также превысили общий лимит. После той же адаптации итог — 232/232.
Ограничители в приложении для тестов не отключаются. Гонка за квоту проверяется
отдельно настоящими одновременными запросами к PostgreSQL.

## Состояние и риски выпуска

На production SEC-06/SEC-07 остаются открытыми до отдельно разрешённого выпуска
и проверки. Код, миграция и конфигурации пока локальные; работающий сервер не менялся.
Сохранились пользовательский файл `0.167.1` и материалы исходного аудита.
Коммита, push, деплоя и перезапуска не было.

Общая строка учёта снимков сериализует их изменения; это сознательная защита
глобальной квоты. Лимиты учитывают JSON, а не весь диск. IP-лимиты делятся
пользователями за NAT; счётчики приложения сбрасываются при перезапуске.
Ресурсный лимит памяти жёсткий, поэтому требуется проверка политики Restart
и обычных сценариев после будущей активации службы.

Предложение коммита: `feat(security): ограничить API, снимки и журнал отказов ИИ`.
Следующий шаг — согласовать коммит; выпуск, миграция и установка конфигураций
требуют отдельного разрешения.
