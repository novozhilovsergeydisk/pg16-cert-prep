# Этап 1 исправлений безопасности — 7 ноября 2026

Я подготовил исправления SEC-01 и SEC-02 из [аудита](README.md): защиту HTTP-парсера и обязательное шифрование почты. Этот отчёт фиксирует результаты локальной подготовки до коммита и выпуска; результат последующего выпуска учитывается в локальной таблице tasks, задачи 203–204.

## Что изменено

- В `server.js` оба JSON-парсера используют `inflate: false`. Сжатые тела отклоняются с HTTP 415 до распаковки. Обычный JSON, предел 2 КБ для отчётов клиента и прежний общий предел 100 КБ сохранены.
- В `src/services/mailer.js` STARTTLS обязателен для портов, отличных от 465. Для 465 сохранён TLS с начала соединения. Проверка сертификата явно включена, минимальная версия TLS — 1.2. Кастомное TCP-соединение и общий срок отправки сохранены.
- Обновлён lockfile: body-parser 2.3.0 → 2.4.0, qs 6.16.0 → 6.17.1, Nodemailer 10.1.0 → 10.3.1, minimatch 10.2.6 → 11.0.5. Версия Express остаётся 5.2.1.
- Для nodemon добавлено адресное `overrides.nodemon.minimatch`: его собственный диапазон ветки 10 не включает исправленную ветку. Сам nodemon остаётся 3.1.14. Изменение правил наблюдения проверяется через настоящий matcher nodemon.
- Добавлены `tests/security.test.js`, `tests/mail-tls.test.js` и команда `npm run test:security`. Эти тесты включены и в общий набор. Прежнее пользовательское добавление backup-lecture.test.js в команду тестирования сохранено.
- README описывает требования TLS, отказ от сжатого JSON и локальные SMTP-проверки. Существующая правка индикатора ожидания и остальные пользовательские файлы сохранены.

## Что проверяют новые тесты

14 сценариев: обычный JSON; gzip, deflate и br на обоих парсерах; повреждённые/лишние сжатые байты без завершения сервера; пределы размеров и ошибочный JSON; правила наблюдения nodemon; отказ SMTP без STARTTLS; успешная отправка только по STARTTLS или TLS с начала соединения; отказ при недоверенном сертификате и несовпадении имени в обоих TLS-режимах.

SMTP-имитаторы слушают только loopback. Ключи сертификатов и реквизиты генерируются на время теста, не входят в репозиторий и не выводятся. Отрицательные проверки подтверждают отказ до передачи AUTH и содержимого письма; успешные — передачу только по TLS.
