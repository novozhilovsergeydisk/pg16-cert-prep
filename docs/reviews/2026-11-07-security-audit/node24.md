# Переход службы на Node.js 24 LTS

Я подготовил адресный переход pg16-cert-prep с Node.js 20.20.2 на 24.22.2 LTS по пункту SEC-03 аудита.
Результат выполнения на сервере и идентификатор выпуска учитываются в локальной задаче 207;
этот документ описывает проверенный способ установки и локальную подготовку.

## Состав изменения

- `scripts/install-node-lts.sh` загружает официальный Linux x86_64 runtime, проверяет подпись manifest
  с закреплённым отпечатком подписанта и SHA-256 архива. Keyring берётся из фиксированного коммита
  nodejs/release-keys. Каталог назначения `/opt/pg16-cert-prep/node-v24.22.2-linux-x64` не перезаписывается.
- `deploy/systemd/20-node-lts.conf` меняет ExecStart и PATH только у pg16-cert-prep. Действующий unit,
  ai.conf и EnvironmentFile сохраняются. `/usr/bin/node`, npm системы и другие службы не меняются.
- `deploy/README.md` описывает предварительные проверки, переключение и откат. README проекта
  рекомендует поддерживаемый LTS и содержит ссылку на эту инструкцию.

Версия 24.22.2 выбрана как актуальный проверенный выпуск поддерживаемой ветки 24 LTS;
это не переход всех приложений сервера на новый глобальный Node.
[Выпуск Node.js](https://nodejs.org/en/blog/release/v24.22.2),
[статус веток](https://nodejs.org/en/about/previous-releases),
[проверка подписи](https://github.com/nodejs/node#verifying-binaries).

## Проверки до переключения

Официальный macOS x64 архив 24.22.2 загружен отдельно во временный каталог и проверен по SHA-256.
На нём выполнены общие и браузерные тесты; зависимости проекта и системный Node на Mac не заменялись.
Тестовые скриншоты восстановлены после прогона, прежние пользовательские изменения сохранены.

На appuse перед установкой сохранены unit, каталог drop-in, исходный commit, версии, хеш
`/usr/bin/node` и состояния служб в `/root/ssh-backups/pg16-node24-207-20261107` с правами 0700.
Проверены 22 результата HTTPS соседних сайтов; их исходное состояние используется для сравнения.

## Критерии приёмки и отката

До переключения Linux runtime должен пройти проверку подписи и SHA-256, загрузить зависимости
и обратиться к БД под pgcert; HTTP/TLS-тесты должны пройти на Node 24. После установки drop-in
проверяется systemd-конфигурация, перезапускается только pg16-cert-prep, затем сверяются
`/proc/<MainPID>/exe`, версия процесса, HTTPS, БД и прежнее состояние остальных служб.

Для отката созданный 20-node-lts.conf переносится из каталога службы в закрытую резервную копию,
затем выполняются daemon-reload и restart только pg16-cert-prep. Исходный unit снова использует
сохранённый `/usr/bin/node`; удаление других drop-in и замена глобального runtime не нужны.

Изменение не включает SSH, обновление пакетов ОС, миграции БД или перезапуск VPN/ботов.
Формулировка: `chore(runtime): отдельный Node.js 24 LTS для службы`.
