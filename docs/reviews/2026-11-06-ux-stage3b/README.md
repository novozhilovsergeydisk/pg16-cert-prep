# UX этап 3b: повторное открытие разбора экзамена

Я добавил сохранение снимка завершённого экзамена и открытие разбора из личной истории. Сводка и разбор ошибок используют один снимок как сразу после завершения, так и при последующем открытии.

В снимке находятся тексты вопросов и вариантов, фактический порядок вариантов, названия тем, выбранные и правильные ответы, пояснения, порог сдачи и итог. Тексты и ключи сервер читает из БД на момент проверки экзамена; клиент передаёт только ответы и проверяемый порядок ключей. Последующие изменения и удаление исходного вопроса не меняют сохранённый разбор. Изменение вопроса во время ещё незавершённого экзамена этим этапом не решается.

В личной истории появился «Открыть разбор», в разборе — «К истории экзаменов». Старые записи без снимка показывают «Сохранена только сводка». GET `/api/exam/history/:id` доступен владельцу записи; чужая, отсутствующая и старая запись возвращают одинаковый 404. В административном просмотре чужих экзаменов кнопок разбора нет.

Снимок, сводка и записи статистики сохраняются одной транзакцией. UUID завершения сохраняется вместе с экзаменом в браузере, включая восстановление старых незавершённых попыток. Уникальность пары пользователь/UUID защищает от параллельной отправки и повторов после потери подтверждения. Повтор с изменёнными ответами/порядком отклоняется с 409. Для совместимости старые API-клиенты могут отправлять запросы без UUID; защита от дублей относится к запросам с UUID, который новый интерфейс передаёт всегда. При ошибке сохранения интерфейс предлагает повторить отправку; неудачный откат приводит к уничтожению соединения.

## Миграция и выпуск

Локальная миграция: `migrations/141_exam_review.sql`; перед применением сохранён полный дамп БД `/private/tmp/pg16-ux-stage3b-1793983258089/database.dump`, каталог 0700, файл 0600. Два последовательных запуска миграции завершились успешно. Миграция 140 из другой задачи не применялась в рамках этого этапа.

На момент завершения локального этапа коммита, push и выпуска не было. При выпуске потребуется резервная копия серверной БД, миграция 141 и перезапуск приложения, поскольку меняется серверный код. Серверные файлы доставляются только через git согласно AGENTS.md.

После отдельного разрешения на выпуск и обновления серверного git-репозитория — команды из root-shell на appuse. Название базы перед выполнением следует сверить с действующей конфигурацией без вывода секретов:

```sh
cd /var/www/pg16-cert-prep
umask 077
stage3b_backup_dir="/root/ssh-backups/pg16-ux-stage3b-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$stage3b_backup_dir"
sudo -u postgres pg_dump -Fc pg16_cert > "$stage3b_backup_dir/database.dump"
```

Только при успешном завершении резервной копии — применить миграцию, каждый запуск должен завершиться успешно:

```sh
sudo -u postgres psql -v ON_ERROR_STOP=1 -d pg16_cert -f migrations/141_exam_review.sql
sudo -u postgres psql -v ON_ERROR_STOP=1 -d pg16_cert -f migrations/141_exam_review.sql
```

Здесь серверные команды не выполнялись.

Предлагаемое описание коммита: `feat(exam): сохранённый разбор экзамена из личной истории`.
