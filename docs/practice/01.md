# Практикум. Установка и управление сервером

Примеры повторяют практику курса к теме: расчёт контрольных сумм в кластере, создание кластера, запуск, проверка и остановка сервера. Установку из исходных кодов (Практика+ курса) здесь не повторяем: нужен только готовый пакет PostgreSQL. Выполняйте на учебном кластере, не на рабочем сервере, в командной строке. Первый пример меняет учебный кластер, второй создаёт отдельный новый, в своём каталоге.

На Debian и Ubuntu утилиты лежат в каталоге /usr/lib/postgresql/16/bin и по умолчанию не входят в PATH. Добавьте его на время работы:

```bash
export PATH=/usr/lib/postgresql/16/bin:$PATH
```

Команды выполняйте от пользователя, которому принадлежит кластер. Ниже каталог данных учебного кластера записан как $PGDATA. Пути, номера процессов и числа файлов в выводе у вас будут другими.

## Пример 1. Расчёт контрольных сумм

Цель: проверить, считаются ли контрольные суммы страниц данных, и включить их утилитой pg_checksums.

Утилита работает только с остановленным кластером. Остановим сервер и спросим его состояние:

```bash
pg_ctl stop -m fast
pg_ctl status
```

```
ожидание завершения работы сервера.... готово
сервер остановлен
pg_ctl: сервер не работает
```

Проверим, посчитаны ли контрольные суммы:

```bash
pg_checksums --check
```

```
pg_checksums: ошибка: контрольные суммы в кластере не включены
```

Включим их. Утилита перепишет все страницы данных и обновит управляющий файл, поэтому на большом кластере это занимает заметное время:

```bash
pg_checksums --enable
```

```
Обработка контрольных сумм завершена
Просканировано файлов: 948
Просканировано блоков: 2865
Записано файлов: 780
Записано блоков: 2865
pg_checksums: синхронизация каталога данных
pg_checksums: модификация управляющего файла
Контрольные суммы в кластере включены
```

Повторная проверка теперь читает каждую страницу и сверяет сумму:

```bash
pg_checksums --check
```

```
Обработка контрольных сумм завершена
Просканировано файлов: 948
Просканировано блоков: 2865
Неверные контрольные суммы: 0
Версия контрольных сумм данных: 1
```

Запустим сервер так, как вы обычно запускаете учебный кластер (с теми же параметрами порта и тем же журналом), и спросим у него самого. Если порт нестандартный, добавьте к psql ключ -p:

```bash
pg_ctl -l server.log start
psql -c "SHOW data_checksums"
```

```
 data_checksums 
----------------
 on
(1 строка)
```

Включить или выключить суммы можно только при остановленном кластере. Попытка сделать это при работающем сервере заканчивается отказом:

```bash
pg_checksums --check
```

```
pg_checksums: ошибка: кластер должен быть отключён
```

Если контрольные суммы вам не нужны, верните прежнее состояние: остановите сервер, выполните pg_checksums --disable и запустите сервер снова.

К вопросам: какой утилитой включают расчёт контрольных сумм в существующем кластере; в каком состоянии должен быть кластер; какой ключ initdb включает суммы при создании кластера.

## Пример 2. Создание кластера и управление сервером

Цель: создать новый кластер, запустить сервер, убедиться, что он работает, и остановить его.

Кластер создаёт утилита initdb. Ключ -k сразу включает контрольные суммы. Каталог должен принадлежать обычному пользователю, не суперпользователю операционной системы:

```bash
export PGDATA=~/pg-practice/data
initdb -k
```

С этого момента переменная PGDATA указывает на новый кластер.

В конце вывода initdb сообщает, как запустить сервер. Пока сервера нет, pg_ctl так и отвечает, а код возврата отличается от нуля:

```bash
pg_ctl status
echo $?
```

```
pg_ctl: сервер не работает
3
```

Запускаем сервер на отдельном порту, чтобы не мешать учебному кластеру. Ключ -w заставляет pg_ctl дождаться, пока сервер начнёт принимать подключения:

```bash
pg_ctl -o "-p 5441" -l ~/pg-practice/server.log -w start
pg_ctl status
```

```
ожидание запуска сервера.... готово
сервер запущен
pg_ctl: сервер работает (PID: 15679)
/usr/lib/postgresql/16/bin/postgres "-D" "/home/user/pg-practice/data" "-p" "5441"
```

Параметры после -o pg_ctl передаёт процессу postgres, их видно во второй строке статуса. Теперь убедимся, что сервер отвечает:

```bash
psql -p 5441 -d postgres -c "SHOW data_directory" -c "SHOW data_checksums"
```

```
       data_directory        
-----------------------------
 /home/user/pg-practice/data
(1 строка)

 data_checksums 
----------------
 on
(1 строка)
```

Пока сервер работает, в каталоге данных лежит файл postmaster.pid. В первой строке номер главного процесса, во второй каталог данных:

```bash
head -n 2 $PGDATA/postmaster.pid
```

```
15679
/home/user/pg-practice/data
```

Остановим сервер и посмотрим, что стало с этим файлом:

```bash
pg_ctl stop -w
pg_ctl status
ls $PGDATA/postmaster.pid
```

```
ожидание завершения работы сервера.... готово
сервер остановлен
pg_ctl: сервер не работает
ls: невозможно получить доступ к '/home/user/pg-practice/data/postmaster.pid': Нет такого файла или каталога
```

При штатной остановке сервер сам удаляет postmaster.pid. По этому файлу pg_ctl и другие утилиты определяют, работает ли сервер.

К вопросам: какая утилита создаёт кластер баз данных; какая утилита запускает, останавливает сервер и показывает его состояние; зачем нужна переменная PGDATA.

## Пример 3. Состояние кластера в управляющем файле

Цель: увидеть, что состояние кластера записано в управляющем файле, а не только в памяти работающего сервера.

Утилита pg_controldata читает управляющий файл кластера напрямую, ей не нужен работающий сервер. Сервер из предыдущего примера остановлен:

```bash
pg_controldata | grep -E "Состояние кластера|Версия контрольных"
```

```
Состояние кластера БД:                выключен
Версия контрольных сумм страниц:      1
```

Запустим сервер и спросим снова:

```bash
pg_ctl -o "-p 5441" -l ~/pg-practice/server.log -w start
pg_controldata | grep "Состояние кластера"
```

```
Состояние кластера БД:                в работе
```

Остановим сервер штатно:

```bash
pg_ctl stop -w
pg_controldata | grep "Состояние кластера"
```

```
Состояние кластера БД:                выключен
```

Версия контрольных сумм равна 1, потому что кластер создан с ключом -k. Состояние «в работе» остаётся в управляющем файле, пока сервер не завершится штатно: если процессы оборвать, при следующем запуске сервер увидит это состояние и выполнит восстановление после сбоя. Подробнее о нём в теме о буферном кеше и журнале.

К вопросам: что показывает pg_controldata; где хранится версия контрольных сумм кластера.

## Уборка

В командной строке:

```bash
rm -r ~/pg-practice
```

В учебном кластере из первого примера контрольные суммы остались включёнными. Если они вам не нужны, верните его в прежнее состояние: укажите его каталог в PGDATA и выполните pg_checksums --disable на остановленном сервере.
