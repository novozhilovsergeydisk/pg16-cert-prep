# Практикум. Утилита psql

Примеры повторяют практику курса к теме: сведения о подключении, постраничный просмотр, вид приглашения, вывод времени выполнения и поведение psql после ошибки в транзакции. Выполняйте на учебном кластере, не на рабочем сервере, в psql под суперпользователем postgres. Хватит одного окна терминала.

В курсе настройки сохраняют в файле .psqlrc в домашнем каталоге. Чтобы не трогать ваш собственный файл, если он есть, здесь используется отдельный файл ~/practice.psqlrc: psql читает тот файл, на который указывает переменная окружения PSQLRC. Задайте её в терминале, из которого будете запускать psql:

```bash
export PSQLRC=~/practice.psqlrc
```

Если нужно подключаться не к стандартному порту, добавляйте к команде psql ключ -p. Адреса, номера портов и размеры в выводе у вас будут другими.

Подготовка, в psql:

```sql
CREATE DATABASE practice;
\c practice
```

## Пример 1. Сведения о подключении и постраничный просмотр

Цель: получить сведения о текущем подключении и настроить программу постраничного просмотра так, чтобы широкий вывод не переносился.

Сведения о подключении выводит команда \conninfo:

```
\conninfo
```

```
Вы подключены к базе данных "practice" как пользователь "postgres" через сокет в "/var/run/postgresql", порт "5432".
```

Список баз данных в подробном виде выводит команда \l+. В нём много столбцов: кроме имени и владельца там кодировка, локаль, права доступа, размер, табличное пространство и описание. Ниже показаны только первые столбцы:

```
\l+
```

```
                                   Список баз данных
    Имя    | Владелец | Кодировка | Провайдер локали | LC_COLLATE  |  LC_CTYPE   | ...
-----------+----------+-----------+------------------+-------------+-------------+-----
 postgres  | postgres | UTF8      | libc             | ru_RU.UTF-8 | ru_RU.UTF-8 | ...
 practice  | postgres | UTF8      | libc             | ru_RU.UTF-8 | ru_RU.UTF-8 | ...
 template0 | postgres | UTF8      | libc             | ru_RU.UTF-8 | ru_RU.UTF-8 | ...
 template1 | postgres | UTF8      | libc             | ru_RU.UTF-8 | ru_RU.UTF-8 | ...
(4 строки)
```

Строка вывода шире экрана, поэтому psql передаёт результат программе постраничного просмотра. По умолчанию это less, и он переносит длинные строки, так что таблица разваливается. Программа задаётся переменной окружения PSQL_PAGER. Установим её только для работы в psql командой \setenv. Команду записываем в файл настроек, чтобы она действовала при каждом запуске:

```bash
cat > ~/practice.psqlrc <<'EOF'
\setenv PSQL_PAGER 'less -XS'
EOF
```

Выйдите из psql командой \q и запустите его снова. Проверим, что переменная установлена, и выведем список баз:

```
\! echo "pager=$PSQL_PAGER"
\l+
```

```
pager=less -XS
```

Теперь таблица показывается без переноса: длинные строки обрезаются по краю экрана, а к скрытым столбцам можно перейти стрелкой вправо. Параметр -S отключает перенос строк, параметр -X не очищает экран при выходе из less, так что после нажатия q результат остаётся на экране. Для остальных программ операционной системы настройка не меняется, потому что \setenv действует только на процесс psql и его дочерние процессы.

К вопросам: какой командой psql выводят список баз данных с размерами; какой переменной окружения задают программу постраничного просмотра; в каком файле хранят настройки, которые psql читает при запуске.

## Пример 2. Приглашение и время выполнения

Цель: поменять вид приглашения на пользователь@база=# и включить вывод длительности каждой команды, причём так, чтобы настройки действовали и после перезапуска psql.

Вид приглашения задаёт переменная PROMPT1. Символ %n подставляет имя пользователя, %/ имя базы данных, %R для обычного приглашения даёт знак =, а %# знак # для суперпользователя. Добавим настройки в тот же файл, а длительность включим командой \timing:

```bash
cat >> ~/practice.psqlrc <<'EOF'
\set PROMPT1 '%n@%/%R%# '
\timing on
EOF
```

Выйдите из psql командой \q и запустите его снова. Первое, что вы увидите, ещё до приветствия psql:

```
Секундомер включён.
```

Приглашение теперь другое, а после каждой команды выводится время:

```
postgres@postgres=# SELECT 1;
 ?column? 
----------
        1
(1 строка)

Время: 0,405 мс
```

Так как настройки лежат в файле, они действуют при каждом запуске. Выйдите и запустите psql ещё раз: сообщение о секундомере и новое приглашение снова на месте. Если выполнить \timing без аргумента прямо в сеансе, режим переключится только до конца этого сеанса, а при следующем запуске файл вернёт его в прежнее состояние.

К вопросам: какая переменная задаёт приглашение psql; какая команда включает вывод длительности выполнения; когда psql читает файл с настройками.

## Пример 3. Ошибка внутри транзакции

Цель: увидеть, что после ошибки открытая транзакция не принимает команды, и как это меняет переменная ON_ERROR_ROLLBACK.

Таблица для опыта, в psql:

```sql
\c practice
CREATE TABLE t (id int PRIMARY KEY);
```

Настройки из предыдущего примера продолжают действовать, поэтому после команд вы будете видеть строки «Время:». В выводе ниже они опущены. Откроем транзакцию, вставим строку и выполним команду, которая завершается ошибкой:

```
BEGIN;
INSERT INTO t VALUES (1);
SELECT 1/0;
INSERT INTO t VALUES (2);
COMMIT;
SELECT * FROM t;
```

```
postgres@practice=# BEGIN;
BEGIN
postgres@practice=# INSERT INTO t VALUES (1);
INSERT 0 1
postgres@practice=# SELECT 1/0;
ОШИБКА:  деление на ноль
postgres@practice=# INSERT INTO t VALUES (2);
ОШИБКА:  текущая транзакция прервана, команды до конца блока транзакции игнорируются
postgres@practice=# COMMIT;
ROLLBACK
postgres@practice=# SELECT * FROM t;
 id 
----
(0 строк)
```

После ошибки транзакция не принимает никаких команд, кроме завершающих. Команда COMMIT здесь тоже откатывает её: в таблице пусто, вставка первой строки пропала вместе со второй.

Теперь включим режим, в котором psql сам спасает транзакцию. Значение on заставляет psql перед каждой командой SQL внутри открытой транзакции ставить точку сохранения и после ошибки откатываться к ней:

```
\set ON_ERROR_ROLLBACK on
BEGIN;
INSERT INTO t VALUES (3);
SELECT 1/0;
INSERT INTO t VALUES (4);
COMMIT;
SELECT * FROM t;
```

```
postgres@practice=# BEGIN;
BEGIN
postgres@practice=# INSERT INTO t VALUES (3);
INSERT 0 1
postgres@practice=# SELECT 1/0;
ОШИБКА:  деление на ноль
postgres@practice=# INSERT INTO t VALUES (4);
INSERT 0 1
postgres@practice=# COMMIT;
COMMIT
postgres@practice=# SELECT * FROM t;
 id 
----
  3
  4
(2 строки)
```

Ошибочная команда отменилась, транзакция осталась рабочей, а остальные изменения зафиксированы. Это настройка psql, не сервера: сервер по-прежнему считает ошибочной всю транзакцию, и без помощи psql поведение было бы как в первом опыте. Режим удобен при работе вручную; в скриптах им пользуются осторожно, потому что ошибка перестаёт останавливать транзакцию.

К вопросам: что происходит с транзакцией после ошибки в одной из её команд; что делает ON_ERROR_ROLLBACK; чем ROLLBACK отличается от отката к точке сохранения.

## Уборка

В psql:

```sql
\c postgres
DROP DATABASE practice;
```

В терминале:

```bash
rm ~/practice.psqlrc
unset PSQLRC
```
