# Практикум. Табличные пространства

Примеры повторяют практику курса к теме: создание табличного пространства, табличное пространство по умолчанию для новой базы, символическая ссылка в PGDATA, параметры табличного пространства. Выполняйте на учебном кластере, не на рабочем сервере. Понадобятся окно psql под суперпользователем postgres и окно командной строки.

Подготовка. Табличному пространству нужен пустой каталог, владелец которого — пользователь операционной системы, от имени которого работает сервер. Ниже это каталог /var/lib/postgresql/ts. На Debian и Ubuntu, в командной строке:

```bash
sudo mkdir /var/lib/postgresql/ts
sudo chown postgres: /var/lib/postgresql/ts
```

Если сервер запущен от вашего пользователя, хватит mkdir без sudo и chown. Каталог данных кластера ниже — $PGDATA. Номера oid у вас будут другими.

## Пример 1. Табличное пространство по умолчанию для новой базы

Цель: понять, откуда новая база данных берёт табличное пространство по умолчанию.

```sql
CREATE TABLESPACE ts LOCATION '/var/lib/postgresql/ts';
\db
```

```
               Список табличных пространств
    Имя     | Владелец |      Расположение
------------+----------+------------------------
 pg_default | postgres |
 pg_global  | postgres |
 ts         | postgres | /var/lib/postgresql/ts
(3 строки)
```

```sql
SELECT datname, spcname
FROM pg_database d JOIN pg_tablespace t ON t.oid = d.dattablespace;
```

```
  datname  |  spcname
-----------+------------
 postgres  | pg_default
 template1 | pg_default
 template0 | pg_default
(3 строки)
```

Сделаем ts табличным пространством по умолчанию для шаблона template1 и создадим новую базу без предложения TABLESPACE:

```sql
ALTER DATABASE template1 SET TABLESPACE ts;
CREATE DATABASE practice;
SELECT datname, spcname
FROM pg_database d JOIN pg_tablespace t ON t.oid = d.dattablespace;
```

```
  datname  |  spcname
-----------+------------
 postgres  | pg_default
 template0 | pg_default
 template1 | ts
 practice  | ts
(4 строки)
```

Новая база получила ts. Это и есть ответ на вопрос курса, почему обычно табличным пространством по умолчанию становится pg_default: база создаётся копированием шаблона template1 и наследует его табличное пространство, а у template1 это pg_default.

Вернём template1 как было:

```sql
ALTER DATABASE template1 SET TABLESPACE pg_default;
```

К вопросам: какое табличное пространство становится табличным пространством по умолчанию для новой базы; что верно для табличного пространства по умолчанию баз данных, созданных из шаблона.

## Пример 2. Символическая ссылка и удаление

Цель: найти в PGDATA ссылку на каталог табличного пространства и увидеть, что непустое пространство удалить нельзя.

```sql
SELECT oid, spcname FROM pg_tablespace;
SELECT oid FROM pg_database WHERE datname = 'practice';
```

```
  oid  |  spcname
-------+------------
  1663 | pg_default
  1664 | pg_global
 16631 | ts
(3 строки)

  oid
-------
 16632
(1 строка)
```

В командной строке:

```bash
sudo ls -l $PGDATA/pg_tblspc
sudo ls /var/lib/postgresql/ts
sudo ls /var/lib/postgresql/ts/*
```

```
lrwxrwxrwx 1 postgres postgres 22 ... 16631 -> /var/lib/postgresql/ts
PG_16_202307071
16632
```

В pg_tblspc лежит символическая ссылка с именем, равным oid табличного пространства. В самом каталоге сервер создал подкаталог с номером версии, а в нём — подкаталог с oid базы practice: там будут файлы её объектов.

Удаляем табличное пространство:

```sql
DROP TABLESPACE ts;
```

```
ОШИБКА:  табличное пространство "ts" не пусто
```

В нём лежит база practice. Переносим её в pg_default и удаляем пространство снова:

```sql
ALTER DATABASE practice SET TABLESPACE pg_default;
DROP TABLESPACE ts;
\db
```

```
     Список табличных пространств
    Имя     | Владелец | Расположение
------------+----------+--------------
 pg_default | postgres |
 pg_global  | postgres |
(2 строки)
```

Сам каталог /var/lib/postgresql/ts сервер не удаляет: он остаётся пустым.

К вопросам: что PostgreSQL создаёт в PGDATA/pg_tblspc для пользовательского табличного пространства; зачем внутри каталога табличного пространства есть подкаталог с версией сервера; что нужно, чтобы удалить табличное пространство командой DROP TABLESPACE.

## Пример 3. Параметры табличного пространства

Цель: задать random_page_cost для табличного пространства pg_default.

```sql
ALTER TABLESPACE pg_default SET (random_page_cost = 1.1);
\db+
```

```
                                   Список табличных пространств
    Имя     | Владелец | Расположение | Права доступа |       Параметры        | Размер | Описание
------------+----------+--------------+---------------+------------------------+--------+----------
 pg_default | postgres |              |               | {random_page_cost=1.1} | 30 MB  |
 pg_global  | postgres |              |               |                        | 605 kB |
(2 строки)
```

Теперь для объектов в pg_default планировщик считает произвольное чтение страницы почти таким же дешёвым, как последовательное (seq_page_cost = 1), и чаще выбирает доступ по индексу. Так обычно настраивают пространства на быстрых дисках.

Вернём значение по умолчанию:

```sql
ALTER TABLESPACE pg_default RESET (random_page_cost);
SELECT spcname, spcoptions FROM pg_tablespace;
```

```
  spcname   | spcoptions
------------+------------
 pg_global  |
 pg_default |
(2 строки)
```

К вопросам: что задают параметры seq_page_cost и random_page_cost.

## Уборка

В psql:

```sql
DROP DATABASE practice;
```

В командной строке:

```bash
sudo rmdir /var/lib/postgresql/ts
```
