# Практикум. Очистка

Примеры повторяют практику курса к теме: как разрастается таблица без очистки, что дают полная и обычная очистка, зачем очистке карта видимости. Выполняйте на учебном кластере, не на рабочем сервере, в psql. Хватит одного окна терминала.

Подготовка:

```sql
CREATE DATABASE practice;
\c practice
```

В практике курса автоочистку отключают на весь сервер параметром autovacuum. Здесь её отключают только для таблиц примера параметром хранения autovacuum_enabled = off: результат тот же, а остальной сервер не затронут. Числа в выводе у вас будут немного другими: значения случайные.

## Пример 1. Без очистки таблица и индекс растут

Цель: увидеть, что изменение строк без очистки увеличивает и таблицу, и индекс, а полная очистка возвращает их к исходному размеру.

```sql
CREATE TABLE t (n numeric) WITH (autovacuum_enabled = off);
CREATE INDEX ON t (n);
INSERT INTO t SELECT random() FROM generate_series(1, 100000);
SELECT pg_size_pretty(pg_table_size('t')) AS table_size,
       pg_size_pretty(pg_indexes_size('t')) AS index_size;
```

```
 table_size | index_size
------------+------------
 4360 kB    | 4408 kB
(1 строка)
```

Меняем половину строк и снова смотрим размер. Повторите эти две команды три раза:

```sql
UPDATE t SET n = n WHERE n < 0.5;
SELECT pg_size_pretty(pg_table_size('t')) AS table_size,
       pg_size_pretty(pg_indexes_size('t')) AS index_size;
```

```
 table_size | index_size
------------+------------
 6512 kB    | 6616 kB
...
 8656 kB    | 7624 kB
...
 11 MB      | 11 MB
```

Каждый UPDATE создаёт новые версии строк, а старые остаются в таблице, и на новые версии появляются новые ссылки в индексе. Без очистки место от старых версий не освобождается для повторного использования.

Полная очистка:

```sql
VACUUM FULL t;
SELECT pg_size_pretty(pg_table_size('t')) AS table_size,
       pg_size_pretty(pg_indexes_size('t')) AS index_size;
```

```
 table_size | index_size
------------+------------
 4336 kB    | 3104 kB
(1 строка)
```

VACUUM FULL переписал таблицу без мёртвых версий и перестроил индекс заново, поэтому индекс стал даже меньше исходного. На время работы таблица заблокирована полностью, даже для чтения.

К вопросам: чем VACUUM FULL отличается от обычной очистки; что верно для VACUUM FULL на разросшейся таблице.

## Пример 2. Обычная очистка после каждого изменения

Цель: увидеть, что обычная очистка не уменьшает файлы, но останавливает их рост.

Продолжаем с той же таблицей. Повторите три раза:

```sql
UPDATE t SET n = n WHERE n < 0.5;
VACUUM t;
SELECT pg_size_pretty(pg_table_size('t')) AS table_size,
       pg_size_pretty(pg_indexes_size('t')) AS index_size;
```

```
 table_size | index_size
------------+------------
 6520 kB    | 4640 kB
...
 6520 kB    | 4640 kB
...
 6520 kB    | 4640 kB
```

После первого раза размер вырос, а дальше не меняется. Обычная очистка удаляет мёртвые версии и ссылки на них из индекса, и освободившееся место занимают новые версии. Операционной системе место, как правило, не возвращается.

К вопросам: возвращает ли обычный VACUUM место операционной системе; к чему приводит отключение автоочистки.

## Пример 3. Карта видимости и сканирование только индекса

Цель: увидеть, как очистка отмечает страницы в карте видимости и как это ускоряет доступ только по индексу.

```sql
CREATE TABLE v (id int PRIMARY KEY, val text) WITH (autovacuum_enabled = off);
INSERT INTO v SELECT g, 'x' FROM generate_series(1, 100000) g;
ANALYZE v;
SET enable_seqscan = off;
SET enable_bitmapscan = off;
EXPLAIN (ANALYZE, COSTS OFF, TIMING OFF, SUMMARY OFF)
SELECT count(id) FROM v WHERE id < 50000;
```

Параметры enable_* только заставляют планировщик выбрать сканирование индекса, чтобы его было видно в плане.

```
                             QUERY PLAN
---------------------------------------------------------------------
 Aggregate (actual rows=1 loops=1)
   ->  Index Only Scan using v_pkey on v (actual rows=49999 loops=1)
         Index Cond: (id < 50000)
         Heap Fetches: 49999
(4 строки)
```

Heap Fetches: 49999 — для каждой найденной строки пришлось заглянуть в таблицу и проверить видимость: страницы ещё не отмечены в карте видимости.

```sql
VACUUM v;
EXPLAIN (ANALYZE, COSTS OFF, TIMING OFF, SUMMARY OFF)
SELECT count(id) FROM v WHERE id < 50000;
```

```
         Heap Fetches: 0
```

Очистка отметила страницы как полностью видимые, и обращаться к таблице больше не нужно.

```sql
UPDATE v SET val = 'y' WHERE id = 10;
EXPLAIN (ANALYZE, COSTS OFF, TIMING OFF, SUMMARY OFF)
SELECT count(id) FROM v WHERE id < 50000;
```

```
         Heap Fetches: 227
```

Одно изменение сняло отметку со всей страницы, где лежала строка, и для всех её строк снова нужна проверка в таблице. До следующей очистки.

```sql
RESET enable_seqscan;
RESET enable_bitmapscan;
```

К вопросам: как карта видимости ускоряет доступ только по индексу; как карта видимости помогает самой очистке.
