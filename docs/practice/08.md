# Практикум. Базы данных и схемы

Примеры повторяют практику курса к теме: размер базы данных, схемы, путь поиска и параметры уровня базы данных. Выполняйте на учебном кластере, не на рабочем сервере, в psql под суперпользователем postgres. Хватит одного окна терминала.

Размеры у вас будут немного другими.

## Пример 1. Размер базы данных и схемы

Цель: создать базу данных, две схемы с таблицами и увидеть, как растёт размер базы.

```sql
CREATE DATABASE practice;
\c practice
SELECT pg_size_pretty(pg_database_size('practice'));
```

```
 pg_size_pretty
----------------
 7694 kB
(1 строка)
```

Пустая база уже занимает несколько мегабайт: при создании она копируется из шаблона template1 вместе с системным каталогом.

Создадим схему app и схему с именем текущего пользователя, postgres, и таблицы в них. Таблица items есть в обеих схемах:

```sql
CREATE SCHEMA app;
CREATE SCHEMA postgres;
CREATE TABLE app.orders (id int, amount numeric);
INSERT INTO app.orders SELECT g, g * 10 FROM generate_series(1, 10000) g;
CREATE TABLE app.items (id int, name text);
INSERT INTO app.items VALUES (1, 'из схемы app');
CREATE TABLE postgres.items (id int, name text);
INSERT INTO postgres.items VALUES (1, 'из схемы postgres');
SELECT pg_size_pretty(pg_database_size('practice'));
```

```
 pg_size_pretty
----------------
 8214 kB
(1 строка)
```

```sql
\dn
```

```
         Список схем
   Имя    |     Владелец
----------+-------------------
 app      | postgres
 postgres | postgres
 public   | pg_database_owner
(3 строки)
```

К вопросам: что такое схема в PostgreSQL; для чего нужны схемы.

## Пример 2. Путь поиска

Цель: сделать таблицы обеих схем доступными без имени схемы, чтобы схема пользователя имела приоритет.

```sql
SHOW search_path;
SELECT * FROM items;
SELECT * FROM orders;
```

```
   search_path
-----------------
 "$user", public
(1 строка)

 id |       name
----+-------------------
  1 | из схемы postgres
(1 строка)

ОШИБКА:  отношение "orders" не существует
```

По умолчанию путь поиска — "$user", public. "$user" означает схему с именем текущего пользователя, поэтому items нашлась в схеме postgres. Схемы app в пути нет, и orders не найдена.

Зададим путь поиска для всех сеансов этой базы данных и переподключимся:

```sql
ALTER DATABASE practice SET search_path = "$user", app, public;
\c practice
SHOW search_path;
SELECT * FROM items;
SELECT count(*) FROM orders;
```

```
     search_path
----------------------
 "$user", app, public
(1 строка)

 id |       name
----+-------------------
  1 | из схемы postgres
(1 строка)

 count
-------
 10000
(1 строка)
```

Имя ищется по схемам слева направо. items нашлась в первой же схеме postgres, а orders — в app.

К вопросам: как PostgreSQL находит таблицу, указанную без имени схемы; что верно для схемы с именем пользователя в пути поиска по умолчанию.

## Пример 3. Параметр уровня базы данных

Цель: сделать так, чтобы в каждом новом сеансе этой базы данных параметр temp_buffers был в четыре раза больше значения по умолчанию.

```sql
SHOW temp_buffers;
ALTER DATABASE practice SET temp_buffers = '32MB';
\c practice
SHOW temp_buffers;
```

```
 temp_buffers
--------------
 8MB
(1 строка)

 temp_buffers
--------------
 32MB
(1 строка)
```

Значение применяется при подключении, поэтому нужно переподключиться. Посмотреть параметры, заданные для баз и ролей, можно командой \drds:

```sql
\drds
```

```
                 Список параметров
 Роль |    БД    |            Параметры
------+----------+----------------------------------
      | practice | search_path="$user", app, public+
      |          | temp_buffers=32MB
(1 строка)
```

В другой базе данных значение прежнее:

```sql
\c postgres
SHOW temp_buffers;
```

```
 temp_buffers
--------------
 8MB
(1 строка)
```

Отдельных вопросов об этом в теме нет: пример взят из дополнительной практики курса.
