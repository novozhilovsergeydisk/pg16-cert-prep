# Практикум. Системный каталог

Примеры повторяют практику курса к теме: описание таблиц и представлений каталога, системные схемы, запросы, которые выполняет psql. Выполняйте на учебном кластере, не на рабочем сервере, в psql под суперпользователем postgres. Хватит одного окна терминала.

Подготовка:

```sql
CREATE DATABASE practice;
\c practice
```

Длинный вывод ниже сокращён многоточием. Номера временных схем и oid у вас будут другими.

## Пример 1. Описание таблицы и представления каталога

Цель: посмотреть, как устроена таблица pg_class и на каком запросе построено представление pg_tables.

```sql
\d pg_class
```

```
                               Таблица "pg_catalog.pg_class"
       Столбец       |     Тип      | Правило сортировки | Допустимость NULL | По умолчанию
---------------------+--------------+--------------------+-------------------+--------------
 oid                 | oid          |                    | not null          |
 relname             | name         |                    | not null          |
 relnamespace        | oid          |                    | not null          |
 reltype             | oid          |                    | not null          |
...
 relkind             | "char"       |                    | not null          |
...
Индексы:
    "pg_class_oid_index" PRIMARY KEY, btree (oid)
    "pg_class_relname_nsp_index" UNIQUE CONSTRAINT, btree (relname, relnamespace)
    "pg_class_tblspc_relfilenode_index" btree (reltablespace, relfilenode)
```

Первичный ключ таблицы — столбец oid. Имена столбцов начинаются с общего префикса rel, по таблице: relname, relkind. Столбец relnamespace хранит oid схемы из pg_namespace.

Для представления команда \d+ показывает ещё и его определение:

```sql
\d+ pg_tables
```

```
                                 Представление "pg_catalog.pg_tables"
   Столбец   |   Тип   | Правило сортировки | Допустимость NULL | По умолчанию | Хранилище | Описание
-------------+---------+--------------------+-------------------+--------------+-----------+----------
 schemaname  | name    |                    |                   |              | plain     |
 tablename   | name    |                    |                   |              | plain     |
...
Определение представления:
 SELECT n.nspname AS schemaname,
    c.relname AS tablename,
    pg_get_userbyid(c.relowner) AS tableowner,
    t.spcname AS tablespace,
    c.relhasindex AS hasindexes,
    c.relhasrules AS hasrules,
    c.relhastriggers AS hastriggers,
    c.relrowsecurity AS rowsecurity
   FROM pg_class c
     LEFT JOIN pg_namespace n ON n.oid = c.relnamespace
     LEFT JOIN pg_tablespace t ON t.oid = c.reltablespace
  WHERE c.relkind = ANY (ARRAY['r'::"char", 'p'::"char"]);
```

pg_tables — удобная обёртка над pg_class: соединяет её с pg_namespace и pg_tablespace и оставляет только таблицы, обычные (r) и секционированные (p).

К вопросам: что выводит команда psql \d pg_class; чем вывод команды \d+ отличается от \d; как обычно устроены имена столбцов в таблицах системного каталога.

## Пример 2. Системные схемы

Цель: увидеть полный список схем базы данных, включая системные, и представления information_schema.

```sql
CREATE TEMP TABLE tmp (id int);
\dn
```

```
        Список схем
  Имя   |     Владелец
--------+-------------------
 public | pg_database_owner
(1 строка)
```

Команда \dn без буквы S не показывает системные схемы. С ней:

```sql
\dnS
```

```
              Список схем
        Имя         |     Владелец
--------------------+-------------------
 information_schema | postgres
 pg_catalog         | postgres
 pg_temp_14         | postgres
 pg_toast           | postgres
 pg_toast_temp_14   | postgres
 public             | pg_database_owner
(6 строк)
```

pg_catalog — системный каталог. information_schema — стандартные представления SQL поверх каталога. pg_toast — toast-таблицы. pg_temp_14 и pg_toast_temp_14 появились из-за временной таблицы: у каждого сеанса своя временная схема.

Представления information_schema:

```sql
\dv information_schema.*
```

```
                                   Список отношений
       Схема        |                  Имя                  |      Тип      | Владелец
--------------------+---------------------------------------+---------------+----------
 information_schema | _pg_foreign_data_wrappers             | представление | postgres
...
 information_schema | columns                               | представление | postgres
...
 information_schema | tables                                | представление | postgres
...
 information_schema | views                                 | представление | postgres
(65 строк)
```

К вопросам: чем information_schema отличается от pg_catalog; что верно для системного каталога.

## Пример 3. Какие запросы выполняет psql

Цель: увидеть, что команды psql вида \d — это обычные запросы к системному каталогу.

```sql
\set ECHO_HIDDEN on
\d+ pg_views
```

```
/******** ЗАПРОС ********/
SELECT c.oid,
  n.nspname,
  c.relname
FROM pg_catalog.pg_class c
     LEFT JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
WHERE c.relname OPERATOR(pg_catalog.~) '^(pg_views)$' COLLATE pg_catalog.default
  AND pg_catalog.pg_table_is_visible(c.oid)
ORDER BY 2, 3;
/************************/

/******** ЗАПРОС ********/
SELECT c.relchecks, c.relkind, c.relhasindex, c.relhasrules, ...
FROM pg_catalog.pg_class c
...
WHERE c.oid = '12028';
/************************/

/******** ЗАПРОС ********/
SELECT a.attname,
  pg_catalog.format_type(a.atttypid, a.atttypmod),
...
FROM pg_catalog.pg_attribute a
WHERE a.attrelid = '12028' AND a.attnum > 0 AND NOT a.attisdropped
ORDER BY a.attnum;
/************************/

/******** ЗАПРОС ********/
SELECT pg_catalog.pg_get_viewdef('12028'::pg_catalog.oid, true);
/************************/

/******** ЗАПРОС ********/
SELECT r.rulename, trim(trailing ';' from pg_catalog.pg_get_ruledef(r.oid, true))
FROM pg_catalog.pg_rewrite r
WHERE r.ev_class = '12028' AND r.rulename != '_RETURN' ORDER BY 1;
/************************/
```

Дальше идёт обычный вывод \d+ pg_views.

psql выполнил пять запросов. Первый находит oid представления по имени в pg_class. Второй читает его свойства из той же pg_class. Третий берёт столбцы из pg_attribute: условия attnum > 0 и NOT attisdropped отбрасывают системные и удалённые столбцы. Четвёртый получает определение функцией pg_get_viewdef. Пятый ищет правила в pg_rewrite. В другой версии psql запросы могут немного отличаться.

```sql
\set ECHO_HIDDEN off
```

К вопросам: какие условия нужны при выборке столбцов таблицы из pg_attribute; что представляет собой тип данных oid.
