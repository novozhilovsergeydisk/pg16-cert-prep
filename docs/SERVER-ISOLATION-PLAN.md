## Что установлено до изменений

- В полной загруженной конфигурации `nginx -T` нет активных директив `fastcgi_pass`. PHP-сайты через этот nginx сейчас не обслуживаются.
- `/var/www/lan-install` — PHP-проект; его конфигурация `sites-available/lan-install.appuse.ru` не подключена. В `/var/www/karina-co` также есть PHP-файл; старые конфигурации этого проекта не подключены. Пользователь подтвердил, что оба проекта можно архивировать.
- Служба `php8.2-fpm` активна и включена в автозапуск. Единственный пул `[inet]` работает от `www-data` через `/run/php/php8.2-fpm.sock`. На момент проверки подключённых клиентов сокета не было. В проверенных systemd-службах и заданиях cron не найдено потребителей этих проектов; найдено только штатное обслуживание PHP в `/etc/cron.d/php`.
- Действующий `fontserver-proxy` тоже работает от `www-data`. Этот пользователь может читать `.env` проекта `lan-install`, поскольку является владельцем. Одна остановка PHP-FPM этот доступ не закроет.
- У `testuser` заблокирован пароль, нет каталога `.ssh`, sudo, процессов и пользовательского cron. Дополнительный источник SSH-ключей и доверенный SSH CA не настроены. Учётная запись имеет оболочку `/bin/bash` и не ограничена сроком действия.
- `testuser` не может читать шесть проверенных файлов настроек: `app-agency/.env`, `dev-infra/.env`, `fontserver.online/server/.env`, `lan-install/.env`, `pg-practikum/.env`, `pg16-cert-prep/.env`. Файлов этого пользователя в `/var/www` не найдено; его домашний каталог и почта сохранены.
- Исходные каталоги: `lan-install` — `www-data:www-data`, `0755`; `karina-co` — `root:root`, `0755`. Родительский каталог `/var/www` принадлежит `root:root`, права `0755`.

Это результат обследования перечисленных конфигураций и путей, а не аудит всех способов доступа к серверу.

## Выполненные изменения

Вместо создания отдельных пулов для неиспользуемых сайтов выполнен следующий согласованный порядок:

1. Сохранить текущие режимы каталогов, состояние службы, оболочку и срок действия `testuser` в закрытый файл состояния. Снять исходные HTTP-коды сайтов и состояния служб.
2. Закрыть доступ приложений к исходным каталогам архивных проектов, изменив только владельца и права верхнего каталога, без рекурсивных изменений:

   ```bash
   chown root:root /var/www/lan-install /var/www/karina-co
   chmod 700 /var/www/lan-install /var/www/karina-co
   ```

3. Остановить PHP-FPM и убрать его из автозапуска:

   ```bash
   systemctl disable --now php8.2-fpm
   ```

4. Явно запретить вход `testuser`, сохранив учётную запись, файлы, UID/GID и существующую блокировку пароля:

   ```bash
   usermod --shell /usr/sbin/nologin --expiredate 1970-01-02 testuser
   ```

5. Проверить, что `www-data` и `testuser` не проходят в каталоги архивных проектов, PHP-FPM остановлен и отключён от автозапуска, учётная запись просрочена и имеет `nologin`. Сравнить HTTP-коды действующих сайтов, состояния и PID их служб с исходными; убедиться, что архивы по-прежнему проходят SHA-256.

nginx и приложения не перезапускались, код не развёртывался. Архивные проекты смогут быть возвращены в работу после восстановления доступа и отдельной настройки их службы.
