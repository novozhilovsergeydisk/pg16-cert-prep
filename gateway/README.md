# Личный помощник PostgreSQL 16

Кнопка «Объяснить подробнее» появляется после сохранённого ответа в тренировке или режиме
«Подходит или нет». В учебном режиме уточняющий диалог относится к текущему вопросу. Доступ определяется
конкретным AI_OWNER_USER_ID, а не ролью admin. По умолчанию функция выключена.

Переключатель «По текущему вопросу / Любая тема» находится в этом же блоке после сохранённого
ответа. По умолчанию выбран текущий вопрос. В режиме «Любая тема» сразу доступно поле ввода,
а шлюз использует общую инструкцию без ограничения PostgreSQL и без контекста карточки.
Смена режима очищает показанный диалог; следующий запрос начинает новый. Уже отправленная
генерация может завершиться, но её ответ не попадёт в новый режим. Кнопка «Новый диалог»
позволяет начать общий диалог заново. Интернет-поиска и инструментов у модели нет.

## Поток запроса

Браузер → appuse (вход, права, сохранённый ответ) → SSH → magenta → OpenRouter.

POST возвращает 202; браузер опрашивает состояние отдельными запросами с обычным тайм-аутом
15 секунд. Генерация выполняется в отдельном процессе. Шлюз ограничивает полную работу 45
секундами, SSH-транспорт приложения — 55 секундами. Ожидание результата на странице — 70
секунд плюс окончание текущего HTTP-запроса. Переход к другой карточке отменяет показ старого
результата, но уже начатая генерация может завершиться.

В приложении нет HTTP-клиента OpenRouter и его API-ключа. Шлюз использует фиксированный HTTPS
адрес, не следует редиректам и не использует прокси из окружения. Заголовки браузера, IP, cookie,
адрес почты и номер пользователя провайдеру не передаются. При отказе SSH прямого fallback нет.
Это ограничение реализации и размещения ключа; отдельный сетевой firewall для процесса сайта
не устанавливается, чтобы не затронуть его почту, БД и соседние сайты.

Модель фиксирована: nvidia/nemotron-3-ultra-550b-a55b:free, reasoning включён. Перед каждым
вызовом проверяются нулевые цены каталога, а provider.max_price ограничивает обе цены нулём.
Платные модели, плагины и инструменты не вызываются. Ошибки 429 не повторяются автоматически.
Тексты запросов, ответов, ключ, SSH stderr и тела ошибок провайдера не журналируются.
Бесплатный endpoint NVIDIA может сохранять отправленный учебный контекст на своей стороне.

Контекст — сохранённый снимок тренировочного вопроса либо вопрос и сохранённый ответ карточки,
пояснения к вариантам и выбранный пользователем ответ. Буквы вариантов преобразуются в видимый
порядок. Для очистки, мониторинга, изоляции и табличных пространств добавлены короткие проверенные
сведения со ссылками на документацию PG16. Поиска по всему курсу и всей документации пока нет.
ИИ не изменяет вопросы, ключи, статистику или базу данных и не выполняет SQL.
В общем режиме сервер проверяет сохранённый ответ и принадлежность карточки, но передаёт
шлюзу только признак общего режима и сообщения нового диалога. Его история и лимиты
учитываются тем же механизмом, что и пояснения PostgreSQL.

При выпуске поддержки общего режима сначала обновить шлюз на magenta, затем сайт на appuse:
новый шлюз совместим с прежними запросами пояснений. На magenta настроен sparse-checkout
`/gateway/`; обновлять его через git, сохраняя этот выбор. Резервные копии создавать с
ограниченными правами отдельно от git-обновления: перед `git pull` использовать umask 022
и проверить чтение обновлённых файлов пользователями pgcert/pg16-ai.

## Ограничения первой версии

- Один активный запрос, максимум 10 попыток за 10 минут и 30 за скользящие 24 часа.
- До шести ответов в одном диалоге; уточнение — до 1000 символов.
- Контекст не обрезается: слишком большой вопрос отклоняется с понятным сообщением.
- История и идемпотентность хранятся в памяти одного процесса, срок доступности — 15 минут.
  Истёкшие записи удаляются при следующих обращениях. Перезапуск теряет диалоги и локальные
  счётчики, но не отменяет лимит бесплатных запросов и бюджет ключа у OpenRouter.
- Нет автоматического перевыпуска истёкшего ключа. Ключ текущего пилота истекает 05.12.2026;
  его обновление — отдельное действие владельца.

## Подготовка выпуска — не выполняется автоматически

Нужны отдельные разрешения на коммит, push, выпуск и настройку серверов. Перед изменениями:
проверить чистоту git-копии appuse, HTTP/HTTPS соседних сайтов, состояние VPN и snt-bot на
magenta; сделать защищённые копии изменяемых SSH-файлов, файла ключа и systemd drop-in.
Существующий ключ OpenRouter не выводить в терминал, diff, журнал или команды.

### magenta

1. После разрешённого коммита получить **тот же коммит через git** в
   /opt/pg16-ai-gateway. Для приватного репозитория использовать отдельный ключ чтения git;
   не передавать личный SSH-agent. Репозиторий и его родительские каталоги должны принадлежать
   root и быть недоступны для записи pg16-ai, его группе и остальным пользователям.
2. Установить права: /etc/pg16-ai — root:pg16-ai, 750;
   /etc/pg16-ai/openrouter.key — pg16-ai:pg16-ai, 600;
   /var/lib/pg16-ai — pg16-ai:pg16-ai, 700. Каталог /var/lib/pg16-ai нужен для блокировки
   одновременных процессов. Скрипт запускается без дополнительных Python-зависимостей.
3. В /home/pg16-ai/.ssh/authorized_keys изменить **только** строку созданного ключа appuse,
   сохранив её публичную часть и комментарий. Опции строки:

   ```text
   from="146.185.235.4",restrict,command="/usr/bin/python3 -I /opt/pg16-ai-gateway/gateway/ai_gateway.py"
   ```

   Публичную часть ключа не выводить, для проверки использовать отпечаток. Это превращает ключ
   в доступ только к шлюзу: команды оболочки, SCP/SFTP и forwarding через него недоступны.
   Административный вход root с Mac остаётся отдельным ключом. sshd перезапускать не нужно.

### appuse

Код сайта доставляется исключительно установленным процессом git: разрешённый коммит в main,
отдельно разрешённый push; на сервере fetch, просмотр HEAD..origin/main, затем pull --ff-only.
Если рабочая копия сервера грязная — остановиться, не очищать её.

Служба сайта работает как pgcert. После резервной копии и получения кода подготовить SSH:

```bash
install -d -o root -g pgcert -m 750 /etc/pg16-ai
install -o pgcert -g pgcert -m 600 /root/.ssh/pg16-ai-foolish-magenta /etc/pg16-ai/ssh_client.key
install -o root -g pgcert -m 640 /root/.ssh/known_hosts_pg16_ai /etc/pg16-ai/known_hosts
install -o root -g pgcert -m 640 /var/www/pg16-cert-prep/gateway/ssh_config.example /etc/pg16-ai/ssh_config
```

Используется уже проверенный ключ сервера из known_hosts_pg16_ai, а не слепое принятие ssh-keyscan.
При смене IP сначала подтвердить ключ сервера, затем обновить оба файла: ssh_config и known_hosts.

В отдельном systemd drop-in для pg16-cert-prep.service задать AI_ENABLED=1 и
AI_OWNER_USER_ID=<проверенный номер аккаунта владельца на рабочем сайте>. Не подставлять id из
локальной тестовой базы и не включать помощника всем администраторам. API-ключ на appuse
не копировать. Перечитать systemd-конфигурацию и перезапустить только pg16-cert-prep после
разрешения на выпуск. Миграции БД для этой функции не нужны.

## Проверка перед включением

1. Из-под pgcert отправить безопасный учебный JSON в ssh -F /etc/pg16-ai/ssh_config -T
   pg16-ai-gateway. Проверить JSON-ответ, cost=0 и срок действия ключа; секрет не печатать.
2. Проверить другой аккаунт, отсутствие кнопки до ответа, оба режима тренировки,
   уточнение, повтор запроса, смену карточки и выход из аккаунта.
3. Проверить SSH-отказ на изолированной тестовой конфигурации. Не останавливать общий sshd
   или VPN ради проверки. Не должно быть второго соединения или прямого вызова OpenRouter.
4. Проверить права ключей и каталогов, статусы соседних сайтов, VPN и snt-bot.
5. Для отката сначала AI_ENABLED=0 и перезапуск только сайта; затем восстановить точечные
   изменения конфигурации из резервных копий. API-ключ не переносить на appuse.

## Локальные проверки

```bash
npm run test:ai
npm test
npm run test:browser
```

Node-тесты используют локальную БД проекта и удаляют только созданные ими записи. Шлюз
тестируется с подменённым HTTP-сервером; реальные API-ключи и запросы к OpenRouter не нужны.
Если Chromium Playwright не установлен, можно задать BROWSER_EXECUTABLE_PATH до установленного
Chrome. Не печатать конфигурацию окружения при диагностике.

Пилот 05.11.2026: нулевой бюджет ключа подтверждён реальными бесплатными запросами с magenta.
В быстром режиме обнаружены ошибки по autovacuum, REPEATABLE READ и pg_statio_user_tables;
основные ответы исправились в отдельных повторениях с reasoning и с контекстом документации.
Это небольшая проверка, не оценка общей точности. Gemma дважды вернула upstream HTTP 429.
